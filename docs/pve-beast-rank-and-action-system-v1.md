# 《梦潮：承道》承道兽层级与兽行系统 v1

版本：v0.4.3D-design

定位：本文是承道兽专题细化，服从 `docs/pve-combat-depth-master-v1.md` 的事件顺序、资源分类和实现路线。本阶段只冻结设计，不实现代码。所有数值均为“首轮测试基线”。

## 1. 当前实现边界

当前已实现：

- V1 `chengdao` 卡牌可以通过 `summon` 生成承道兽。
- 承道兽进入中央战场。
- 承道兽显示攻击、命源、侧性、道脉和承道分类。
- 每只承道兽可以进行基础攻击。
- 承道兽死亡会通知负棺僧“送归”被动。

当前未实现：

- source card 与战场单位的正式绑定生命周期。
- 阵位容量消耗差异。
- 高阶承道兽。
- token 承道兽。
- 承道兽主动技能。
- 冷却。
- 死亡后按 `death_destination` 回到弃牌堆或消耗堆。
- 敌人系统性攻击承道兽。

## 2. 层级

承道兽分为四层：

### 2.1 ordinary：普通承道兽

首轮实现层级。

特征：

- 占 1 点阵位容量。
- 数值中等。
- 每回合通常获得 1 次兽行。
- 通常执行普通攻击。
- 最多一个简单能力。
- 死亡后默认进入弃牌堆。

### 2.2 advanced：高阶承道兽

首轮实现层级，但晚于 ordinary 完成。

特征：

- 占 2 点阵位容量。
- 同时最多存在 1 只高阶承道兽。
- 有主动技能和一个被动或死亡能力。
- 主动技能消耗本回合兽行。
- 死亡后默认进入消耗堆。
- 需要明确召唤条件，不能只是更大的普通兽。

### 2.3 token：衍生承道兽

未来层级。

特征：

- 由卡牌、敌人、事件或 Boss 临时生成。
- 不进入普通牌组。
- 死亡后直接消失。
- 是否占阵位由生成效果明确声明。

### 2.4 unique：唯一承道兽或道主眷兽

未来层级。

特征：

- 通常与道主、事件或命途绑定。
- 可以占 3 点阵位容量。
- 同时通常只能存在 1 只。
- 需要专门 UI 和获得来源，不进入普通奖励池。

第一阶段只实现 ordinary 和 advanced。

## 3. 阵位容量

首轮测试基线：

- 总容量：3。
- 普通兽占 1。
- 高阶兽占 2。
- 未来唯一兽可占 3。
- 同时最多存在一只高阶兽。

容量检查顺序：

```text
合法性检查
→ 目标与容量检查
→ 支付费用
→ 从手牌移除
→ summon effect
```

规则：

- 容量不足时不得扣费。
- 容量不足时不得从手牌移除。
- 容量不足时不得执行任何其他效果。
- 同一张召唤牌不能因为多次 UI 点击生成两个单位。
- 高阶兽上场时若已有高阶兽，失败原因必须明确显示。

建议字段：

- `board_cost`
- `beast_rank`
- `summon_requirement`

## 4. 职责

承道兽职责用于 UI、奖励池和敌人意图判断。

### 4.1 warrior：战兽

职责：

- 主要提供攻击。
- 生命中等或偏低。
- 适合处理敌人、核心和 Boss 部位。

设计风险：

- 不能只做高攻击低互动。
- 应与道息、道脉、死亡或阵位产生关系。

### 4.2 guardian：守兽

职责：

- 主要保护玩家或其他承道兽。
- 生命较高。
- 未来可以拦截敌人攻击或提供守阵。

设计风险：

- 不能让玩家永久无伤。
- 敌人需要有绕过、传导或攻击承道兽的方式。

### 4.3 spirit：灵兽

职责：

- 提供功能、抽牌、道息、道脉、回潮或职业资源。
- 数值通常较低。

设计风险：

- 不应堆叠过多被动触发器。
- 功能必须容易读懂。

## 5. 兽行

兽行是承道兽每回合可执行动作的次数。

首轮测试基线：

- 每只承道兽每个玩家回合获得 1 次兽行。
- 普通兽通常使用普通攻击。
- 少数普通兽可以用一个简单能力替代攻击。
- 高阶兽可以在普通攻击和主动技能之间选择。
- 主动技能消耗本回合兽行。
- 高阶技能可有 1 到 3 回合冷却。

规则：

- 已使用兽行的承道兽显示“已行动”。
- 兽行不与道主主动技能共享次数。
- 死亡承道兽不能继续行动。
- 敌人回合不会自动恢复己方兽行。
- 多波战斗中是否刷新兽行由波次规则明确声明。

建议字段：

- `action_points`
- `has_acted`
- `active_skill`
- `cooldown`
- `cooldown_remaining`

## 6. 能力预算

### 6.1 普通兽

普通兽最多一个简单能力，从以下四类中选择一类：

- 入场能力。
- 被动能力。
- 主动能力。
- 死亡能力。

普通兽示例预算：

- 1 费：攻 2 到 5，命源 5 到 12。
- 2 费：攻 5 到 8，命源 9 到 17。

### 6.2 高阶兽

高阶兽拥有：

- 一个主动技能。
- 一个被动或死亡能力。

限制：

- 不堆叠大量触发器。
- 不做“所有属性都更高”的普通兽。
- 必须要求玩家围绕召唤条件、阵位和兽行做选择。

## 7. 生命周期

冻结生命周期：

```text
手牌
→ 召唤
→ 战场单位绑定 source_card_instance_id
→ 死亡
→ 根据 death_destination 归堆
```

规则：

- 普通兽死亡进入弃牌堆。
- 高阶兽死亡进入消耗堆。
- token 死亡直接消失。
- 驻场时卡牌实例不得进入抽弃循环。
- 战斗结束时存活兽在下一场牌组初始化时恢复为卡牌实例。
- 如果 source card 找不到，必须记录错误并使用安全兜底，不得静默复制新牌。

建议字段：

- `source_card_instance_id`
- `death_destination`
- `is_token`
- `summon_id`
- `owner_id`

## 8. 数据字段预留

承道兽卡牌或 summon effect 建议字段：

- `beast_rank`
- `beast_role`
- `board_cost`
- `action_points`
- `source_card_instance_id`
- `death_destination`
- `active_skill`
- `passive`
- `cooldown`
- `summon_requirement`

当前 V1 卡池已有：

- `summon_id`
- `attack`
- `life`
- `side`
- `dao_tags`
- `chengdao_kind`
- `death_destination`
- `is_special`

未来 v0.4.4 需要补齐：

- source card 绑定。
- board cost。
- beast rank。
- death destination 的实际归堆。

## 9. 三只高阶兽设计

以下只设计，不实现。

### 9.1 宰衡君：镇衡玄犼

层级：advanced。

职责：guardian / spirit。

召唤条件：

- 本回合已获得至少 10 点阵势，或本场战斗已触发衡界 3 次。

阵位占用：

- 占 2 点。
- 场上已有高阶兽时不能召唤。

数值定位：

- 攻 4，命源 20。
- 数值不是亮点，核心是稳定边界。

主动技能：界线归衡

- 消耗 1 次兽行。
- 获得 5 点阵势。
- 下一次火脉积蓄减少 2。
- 冷却 2 回合。

被动：称量守界

- 每回合第一次玩家获得阵势时，若阵势没有溢出为无效防御，记录 1 次衡定。
- 未来可与衡印接口联动。

与道主循环互动：

- 帮宰衡君制造精准防御窗口。
- 与“封脉界约”共同减少道脉积蓄。

为什么不是高数值普通兽：

- 它的价值来自减少道脉风险和稳定衡界触发，不来自更高攻击。

### 9.2 织夜君：缝世夜麟

层级：advanced。

职责：spirit / guardian。

召唤条件：

- 手牌中至少有 2 张凝梦牌，或本场战斗已有 3 张凝梦牌被保留过。

阵位占用：

- 占 2 点。

数值定位：

- 攻 3，命源 18。

主动技能：缝梦留痕

- 消耗 1 次兽行。
- 选择 1 张手牌，给予 1 层梦痕。
- 若该牌已有凝梦，改为抽 1 张。
- 冷却 2 回合。

被动：残世不醒

- 每回合结束时，若玩家保留了至少 2 张凝梦牌，缝世夜麟获得 2 点命源恢复。

与道主循环互动：

- 扩大留宵收益。
- 让保留牌成为长期运营，而不是单纯不弃牌。

为什么不是高数值普通兽：

- 它本身攻击偏低，价值在手牌状态与凝梦运营。

### 9.3 负棺僧：背棺古犀

层级：advanced。

职责：warrior / guardian。

召唤条件：

- 本场战斗已有己方承道兽死亡，或已有 2 张牌进入消耗堆。

阵位占用：

- 占 2 点。

数值定位：

- 攻 6，命源 18。

主动技能：代葬冲

- 消耗 1 次兽行。
- 对敌人造成 8 点伤害。
- 将玩家身上最多 2 点火脉积蓄转移给背棺古犀。
- 冷却 2 回合。

死亡能力：棺响送归

- 死亡时触发送归。
- 若死亡时身上有道脉积蓄，获得 1 枚余骨。

与道主循环互动：

- 是负棺僧承受、转移、死亡收益的核心载体。
- 与“负棺代受”共享选择己方承道兽的目标系统。

为什么不是高数值普通兽：

- 它主动承担道脉风险，并通过死亡转化收益。

## 10. 与 v0.4.4 的关系

v0.4.4 应优先实现：

- source card 与承道兽关联。
- 三点阵位容量。
- ordinary / advanced 层级字段。
- 死亡归堆。
- 基础兽行。

不应在 v0.4.4 同时实现：

- 三只高阶兽完整技能。
- 复杂献祭。
- 多波 Boss。
- 多种道脉。

## 11. 人工决定事项

- `source_card_instance_id` 是否直接存 card instance id，还是存独立 runtime id。
- 高阶兽是否允许通过奖励直接获得，还是必须事件解锁。
- token 是否占阵位。
- 存活承道兽跨波次是否保留当前命源。
- 敌人攻击承道兽时，guardian 是否可以拦截。
