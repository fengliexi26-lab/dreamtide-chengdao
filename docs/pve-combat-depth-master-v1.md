# 《梦潮：承道》PVE 战斗深度总纲 v1

版本：v0.4.3D-design

定位：本文件是 PVE 战斗系统的唯一总纲。承道兽层级、Run 地图房间、道主人物命途等专题文档必须服从本文的事件顺序、资源分类和实现边界。

本阶段只冻结设计，不代表代码已经实现。所有数值均为“首轮测试基线”，不是永久数值。

## 1. 当前问题审计

当前已经实现或接近可用的内容：

- PVE RunState 与九宫格道主选择。
- 三位开放道主：宰衡君、织夜君、负棺僧。
- V1 卡池 39 张和三套 V1 初始牌组。
- `PveCardV1Catalog` 加载、校验和构造独立战斗实例。
- `PveCardEffectAdapter` 解析结构化 `effects`。
- 抽牌堆、弃牌堆、消耗堆。
- 固定抽 5、回合结束自动弃非凝梦手牌。
- 阵势、道息、回潮显示与基础变更。
- 承道兽召唤、上场和基础攻击。
- 三位道主被动：衡界、留宵、送归。

当前已执行的 V1 phase-1 效果集中在：

- `deal_damage`：造成伤害。
- `gain_formation`：获得阵势。
- `draw`：抽牌。
- `gain_daoxi`：获得道息。
- `gain_reflux` / `reduce_reflux`：调整回潮。
- `summon`：简单召唤承道兽。

因此现有决策仍然偏同质化：玩家多数时候只是在比较当前道息下的伤害、阵势、抽牌和召唤效率。承道兽死亡、道脉积蓄、状态互动、敌人意图压力、Boss 阶段变化尚未形成稳定的第二层决策。

本阶段统一决定：

- V1 卡池继续作为 PVE 主线卡池。
- 旧 `cards_v0.json` 只作为兼容和历史参考，不再指导新战斗深度。
- 当前 BattleScene 中仍残留 PVP / Match 兼容路径，但正常项目流以 PVE 为准。
- “道主道击”作为旧原型行为停止扩展，未来替换为“道主主动技能”。

## 2. 五个核心决策维度

以后设计卡牌、敌人、道痕、命器、事件和 Boss 时，必须围绕以下五个维度至少回应一个问题，而不能只提高数值。

### 2.1 命源与持续生存

命源是 Run 的长期压力，而不是单场战斗的可随意刷新资源。玩家应在短期胜利和长期风险间做选择。

设计问题：

- 这张牌或这个房间是否改变本场受伤概率？
- 是否让玩家用命源换牌组强度、回潮、道主势或路线信息？
- 过度保守是否会导致输出不足或错过奖励？

### 2.2 阵势与精准防御

阵势不是简单护甲数值，而是“知道敌人意图后精确应对”的核心。阵势牌应在敌人意图、道脉积蓄和道主被动之间产生差异。

设计问题：

- 为什么这一回合需要这么多阵势？
- 是否存在“刚好挡住”“完全挡住”“挡住但仍积蓄道脉”的不同结果？
- 是否有敌人攻击承道兽、传导攻击或多段攻击来改变防御判断？

### 2.3 道息、手牌和出牌顺序

道息决定当回合能做几件事，手牌决定选择空间，出牌顺序决定触发窗口。优秀卡牌应让玩家关心“先打哪张”。

设计问题：

- 是否先获得道息再打高费牌？
- 是否先召唤承道兽再触发强化或送归？
- 是否为了凝梦留牌而牺牲当前效率？
- 是否有 0 费、抽牌、消耗带来的循环风险？

### 2.4 承道兽阵位、兽行与死亡

承道兽是《梦潮：承道》的核心差异，不是普通随从皮肤。阵位容量、兽行、死亡归堆和道主被动共同构成承道兽运营。

设计问题：

- 这只承道兽占用多少阵位？
- 它本回合应该攻击、防守、使用主动技能还是等待死亡收益？
- 它死亡后回到弃牌堆、消耗堆还是消失？
- 负棺僧是否愿意主动让某只兽死亡？

### 2.5 道脉积蓄、清除、转移和失衡

道脉不是传统元素克制表，而是战斗中的失衡过程。玩家和敌人都可以制造、缓解或转移道脉积蓄。

设计问题：

- 为什么现在增加积蓄而不是直接造成伤害？
- 是否要清除积蓄、延后失衡或转移到承道兽？
- 抗性是改变积蓄效率，还是改变失衡后的状态？
- 高回潮是否让地图和敌人更危险但也更有收益？

每张新卡必须回答：

- 为什么现在使用？
- 什么情况下不应使用？
- 与什么资源或卡牌联动？
- 是否只是在提高数值？

## 3. 统一事件顺序

### 3.1 卡牌结算顺序

冻结为：

```text
合法性检查
→ 目标与容量检查
→ 支付费用
→ 从手牌移除
→ 按 effects 顺序执行
→ 伤害与阵势结算
→ 道脉积蓄变化
→ 道脉失衡检查
→ 单位死亡检查
→ 死亡、送归和被动触发
→ Boss 阶段转换
→ 卡牌归堆
→ UI 刷新
```

规则：

- 合法性失败时不扣费、不移牌、不执行效果、不归堆。
- 容量不足时不扣费、不移牌、不执行效果。
- `effects` 必须按数据顺序结算。
- 同一张卡不能同时进入弃牌堆和消耗堆。
- 道法牌结算后进入弃牌堆或消耗堆。
- 承道兽牌在召唤成功后生成战场单位，source card 归属规则在 v0.4.4 实现前不得再扩大假设。
- 死亡单位不能继续行动。
- 多单位同时死亡时使用稳定顺序：玩家方从左到右，敌方按显示顺序。
- 同一事件不能重复通知同一个触发器。
- 触发队列必须设置最大深度保护，首轮测试基线为 32 层。

### 3.2 回合顺序

冻结为：

```text
玩家回合开始状态
→ 恢复道息
→ 抽牌
→ 玩家操作
→ 凝梦和回合结束效果
→ 留宵
→ 敌人行动
→ 敌人回合结束状态
→ 灼脉等持续效果
→ 下一回合
```

规则：

- 道主主动技能只能在玩家操作阶段使用。
- 道主主动技能不能插入正在结算的卡牌效果。
- 敌人意图必须在玩家操作前公开。
- 敌人行动中产生的死亡和触发必须在进入下一回合前结算完毕。
- UI 刷新发生在稳定结算点，不在触发队列中间暴露半状态。

## 4. 状态和资源分类

### 4.1 战斗状态

代表可显示、可增减、可持续的战斗状态。

示例：

- 灼脉。
- 易伤。
- 守阵。
- 虚弱、缚行、护主等未来状态。

### 4.2 职业资源

代表道主或职业循环的专属资源。

示例：

- 衡印。
- 余骨。
- 道主势。
- 未来饮潮、缺名、灯火等资源。

职业资源不必全部做成状态对象，但必须能被事件系统和 UI 查询。

### 4.3 卡牌实例状态

绑定在战斗卡牌实例上，不修改原始 JSON。

示例：

- 梦痕。
- 临时减费。
- 本战斗升级。
- 本回合额外效果。
- retained_turns 等未来字段。

### 4.4 道脉积蓄

道脉积蓄是独立的失衡计量。

首轮实现只做：

- 火脉积蓄。

未来扩展：

- 灾脉、潮脉、梦脉等其他道脉积蓄。
- 复合道脉反应。

### 4.5 Boss 状态

Boss 状态用于阶段和特殊规则。

示例：

- 当前阶段。
- 阶段资源。
- 阶段护盾。
- 暴露核心。
- 环境机关开关。

### 4.6 状态建议字段

状态数据建议字段：

- `status_id`
- `stacks`
- `max_stacks`
- `duration`
- `tick_timing`
- `source_id`
- `target_id`
- `visible`
- `dispellable`
- `tags`

统一决定：

- 不把所有资源强行实现为同一种状态对象。
- 所有状态和资源必须提供统一事件查询与 UI 查询接口。
- 显示文本不能驱动效果判定。

## 5. 道脉与火脉规则

### 5.1 道脉原则

- 不采用传统元素绝对克制表。
- 道脉代表不同规则与失衡现象。
- 第一版只实现火脉垂直切片。
- 抗性未来影响积蓄效率，不做普遍完全免疫。

### 5.2 火脉首轮测试基线

- 失衡阈值：10。
- 达到阈值后扣除 10。
- 超出部分保留。
- 首次触发灼脉 3 层。
- 再次触发增加 2 层。
- 灼脉最多 6 层。
- 目标回合结束时造成等于当前层数的伤害。
- 结算后层数减少 1。
- 灼脉伤害先扣阵势，再扣命源。
- 不跨战斗保留。

### 5.3 阵势与积蓄

- 攻击对命源造成伤害：完整积蓄。
- 攻击击破阵势：完整积蓄。
- 攻击完全被阵势挡住：积蓄减半并向下取整。
- “传导”攻击即使完全被挡也施加完整积蓄。
- 敌人意图必须明确显示是否传导。

### 5.4 第一版 effect

首轮需要新增或接入：

- `add_pulse_buildup`
- `reduce_pulse_buildup`
- `apply_status`
- fire threshold check

预留但延期：

- `transfer_pulse_buildup`
- `trigger_pulse_break`
- `pulse_resistance`
- 多种道脉。
- 复合道脉反应。

## 6. 道主被动和主动技能

正式取消长期设计中的“道主免费普通伤害攻击”。当前已有道主道击仅作为旧原型能力，不继续扩展。

### 6.1 道主结构

每位道主拥有：

- 一个持续被动。
- 一个装备中的主动技能。

主动技能规则：

- 不进入牌组。
- 只在玩家操作阶段使用。
- 每回合最多使用一次。
- 目标无效时不消耗资源。
- 卡牌结算中不能使用。
- 战斗结束后重置本场战斗内主动技能状态。

### 6.2 统一资源：道主势

首轮测试基线：

- 上限 3。
- 战斗开始 1。
- 主动技能消耗 3。
- 每回合最多获得 1。
- 每场战斗重置。
- 暂不跨战斗保留。

### 6.3 宰衡君：封脉界约

职业循环：

```text
建立阵势
→ 精准衡定并获得衡印
→ 裁决或资源转化
```

道主势来源：

- 衡界成功触发或完成精准防御。
- 每回合最多一次。

主动技能“封脉界约”首轮测试基线：

- 获得 6 点阵势。
- 下一次获得的道脉积蓄减少 4。
- 持续至下个玩家回合开始。
- 只能抵挡一次积蓄来源。
- 完全抵消时未来可获得 1 枚衡印。
- 衡印奖励可延期，但接口必须保留。

依赖系统：

- 道脉系统。
- 职业资源系统。
- 事件队列。
- UI 状态显示。

### 6.4 织夜君：夜覆残世

职业循环：

```text
保留凝梦牌
→ 积累梦痕
→ 启封形成爆发回合
```

道主势来源：

- 留宵在一个回合内至少提供 2 点阵势。
- 每回合最多一次。

主动技能“夜覆残世”首轮测试基线：

- 选择一种正在积蓄的道脉。
- 本回合达到阈值时暂缓失衡。
- 下个玩家回合开始减少 3 点积蓄。
- 随后立即恢复正常判定。
- 同一道脉解除封存后一回合内不能再次封存。
- 不能无限延期。

依赖系统：

- 道脉系统。
- 状态容器。
- 多目标或目标类型选择系统。
- 回合开始事件。

### 6.5 负棺僧：负棺代受

职业循环：

```text
召唤和标记承道兽
→ 控制死亡与送归
→ 使用余骨完成资源或伤害爆发
```

道主势来源：

- 己方承道兽完成有效死亡或送归。
- 每回合最多一次。

主动技能“负棺代受”首轮测试基线：

- 选择一只己方承道兽。
- 将玩家身上一种道脉最多 5 点积蓄转移给它。
- 转移后立即检查失衡。
- 没有合法承道兽时不可使用。
- 若其在下个玩家回合前死亡，触发送归。
- 未来额外获得 1 枚余骨。

依赖系统：

- 承道兽死亡系统。
- 道脉系统。
- 职业资源系统。
- 多目标选择系统。

## 7. 敌人、精英与 Boss

### 7.1 机制预算

普通敌人：

- 0 到 1 个被动。
- 2 到 3 种行动。
- 一个核心机制。
- 固定或半固定行动序列。

强敌：

- 1 个被动。
- 3 种行动。
- 一个简单条件变化。

精英：

- 1 到 2 个被动。
- 3 到 4 种行动。
- 一个条件行动或反应。
- 可以携带随从或使用多波战斗。

Boss：

- 2 个左右核心被动。
- 4 到 6 种行动。
- 至少两个阶段。
- 公开阶段转换条件。
- 一个明确的战斗命题。

隐藏 Boss：

- 可以改变规则。
- 关键规则、致命技能和转换条件必须公开。

### 7.2 敌人行动支持方向

- 攻击玩家。
- 攻击随机或指定承道兽。
- 群体攻击。
- 增加道脉积蓄。
- 引发道脉失衡。
- 获得阵势。
- 强化自身。
- 召唤随从。
- 施加状态。
- 条件行动。
- 阶段技能。

### 7.3 敌人意图显示

敌人意图必须显示：

- 技能名。
- 目标。
- 伤害。
- 攻击次数。
- 道脉积蓄。
- 是否传导。
- 条件分支。
- 是否攻击承道兽。
- 是否为阶段技能。

禁止：

- 无预告秒杀。
- 隐藏伤害倍率。
- 普遍完全免疫。
- 第一次遭遇必然无法应对的机制。

## 11. 旧规则冲突和本阶段统一决定

发现的冲突：

- 旧 PVP / Match 文档中存在三局轮换、人物阵列和玩家二 UI；当前主线已转为 PVE Run。
- 旧道主道击是每回合免费微额攻击；未来设计正式取消，改为消耗道主势的主动技能。
- 旧卡池含人物、道痕、命器、法阵、伏法、域界等混合类型；V1 active 卡池首批只允许 `daofa` 和 `chengdao`。
- 旧承道兽死亡曾直接进入玩家弃牌数组；V1 需要 source card 绑定和正式死亡归堆。
- 旧文本字段可驱动效果；V1 卡牌必须以结构化 `effects` 和 `keywords` 为准。
- 旧 BattleScene 中仍有 `discard_phase` 兼容分支；PVE 主流程不再使用手动弃牌阶段。

统一决定：

- 新设计以 PVE V1 主线为准。
- 所有未实现内容必须写作“未来设计”或“首轮测试基线”。
- v0.4.4 前不得把高阶兽、道脉、主动技能、多敌人写成已完成系统。

## 12. 进入 v0.4.4 前仍需人工决定

- 承道兽驻场时 source card 是保留在战场单位内，还是移动到隐藏 attached 区。
- 普通兽死亡进弃牌堆时应回到原卡牌实例，还是生成新的基础卡实例。
